# PH-A-7_260818 — PH-B-35 모바일 대응 검수와 화면 정리

8.18 상무님 협의를 앞두고 `PH-B-35/` 전환본을 화면으로 훑으며 고친 세션.
모바일에서 레이아웃이 깨지는 원인 하나를 잡고, 이어서 페리가 화면을 보며 지적한 것들을 순서대로 반영했다.

---

## 배경 (Why)

- 260817 세션에서 만든 이미지→텍스트 전환본(`PH-B-35/`)은 데스크톱 기준으로만 확인돼 있었다.
- 페리의 첫 지적은 **"모바일 대응이 안 되어 있다"**. 실제로 CSS 는 모바일 우선으로 짜여 있었지만
  서브페이지 6곳이 좁은 화면에서 통째로 밀려 나가고 있었다.
- 이후 검수 주소를 폰으로 열어 보며 발견한 것들을 그때그때 고쳐 올리는 방식으로 진행했다.

### 반영 방식 — 260818 확정

- **검수용 확인은 GitHub Pages, 실서버 호스팅은 Cloudflare Pages.** 두 갈래로 간다.
  > ⚠️ 260817 로그의 "8.18 협의 후 GitHub Pages 끄기" 결정은 이 지시로 대체됐다. 검수용으로 계속 켜 둔다.
- 수정하면 **커밋 → 푸시 → Pages 반영 확인까지 묻지 않고 끝낸다.** 매번 "커밋할까요"를 묻지 않는다.

## 과정 (How)

### 1. 검수 도구 — 크롬 확장이 멈춰 헤드리스 크롬으로 갈아탐

- `claude-in-chrome` 확장으로 시작했으나 `resize_window` 가 먹지 않았다. 창은 "성공"으로 응답하는데
  `window.innerWidth` 는 1393 그대로였다.
- iframe 안에서 14개 페이지를 순회하는 검사 스크립트를 넣자 **렌더러가 얼어 CDP 45초 타임아웃**.
  이후 `navigate` 조차 응답하지 않았다.
- **헤드리스 크롬 CLI 로 전환.** 이쪽이 훨씬 안정적이었다.

```
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-gpu --hide-scrollbars \
  --window-size=400,1420 --screenshot=out.png \
  --virtual-time-budget=6000 "http://localhost:8777/..."
```

- > ⚠️ **함정** — `--window-size=390,1400` 으로 직접 찍으면 **오른쪽이 잘린다.** macOS 헤드리스는
  창 최소폭 제약이 있어 실제 뷰포트가 더 넓게 렌더되고 캡처만 390px 로 잘린다.
  처음엔 이걸 레이아웃 버그로 잘못 읽었다.
- **해결** — 폭을 지정한 iframe 에 페이지를 넣고 그 창을 찍는다. 임시 파일 `_shot.html` 을
  서버 루트(= `PH-B-35/`)에 두고 `?p=greeting.html&w=390&h=1400` 로 호출. 검사용 `_audit.html` 도 같은 방식.
  같은 오리진이어야 `contentDocument` 에 접근할 수 있어 스크래치패드가 아닌 레포 안에 둬야 했다.
  **작업 끝나고 둘 다 삭제했다.**

### 2. 원인 — 그리드 칸의 기본 최소폭

- 증상: 인사말·연혁·조직도·설비현황·인증현황·오시는길 6개 페이지가 390px 화면에서 `docW = 635`.
  본문 오른쪽이 화면 밖으로 나갔다.
- 원인: `.layout` 은 CSS Grid 인데 **그리드 칸의 기본 최소폭이 내용 크기(`min-width: auto`)** 다.
  안쪽의 줄바꿈 없는 알약 메뉴(`white-space: nowrap`)와 `min-width: 620px` 짜리 표가
  칸을 615px 로 벌려 놓고 있었다.
- 넘치지 않은 페이지(제품·도면·품질방침 등)는 좌측 메뉴 항목 수가 적어 우연히 걸리지 않았을 뿐이다.

```css
.layout > * { min-width: 0; }
```

- 이 한 줄로 6개 페이지가 모두 해소됐다. **320·390·480·768·900px 전부 가로 넘침 0**, 데스크톱 1280px 회귀 없음.

### 3. 같이 나온 모바일 문제 3건

1. **좌측 메뉴에서 현재 위치를 알 수 없었다** — 좁은 화면에서 메뉴가 가로 스크롤 줄(350→615px)이 되는데,
   활성 항목이 뒤쪽이면 화면 밖에 있었다. `nav.js` 에서 로드 시 가운데로 당긴다.
2. **설비현황 5열 표가 2열만 보였다** — 348→620px 스크롤 컨테이너인데 더 있다는 신호가 없었다.
   720px 이하에서 `표를 좌우로 밀어 나머지 항목을 볼 수 있습니다` 안내를 띄운다.
3. **상단 고객센터 번호가 링크가 아니었다** — 꼬리말 번호만 `tel:` 이었다. 항상 보이는 쪽이 안 눌리고 있었다.

- 손대지 않은 것: 본문 인라인 링크·꼬리말 링크의 탭 영역이 17~25px(권장 44px). 화면이 깨지는 게 아니고
  고치면 문단 줄간격이 벌어져 **별건으로 남겼다.**

### 4. 공지사항 — 제목 겹침과 CSS 특정성

- 글 제목 앞의 초록 막대가 글자와 겹쳐 있었다. 인라인 `style="padding-left:0"` 로 여백만 지우고
  `::before` 막대는 남겨 둔 탓.
- `.post__title` 클래스로 분리해 막대를 없앴는데 이번엔 **제목만 본문보다 14px 안쪽으로 들어갔다.**
  - 원인: `.content h2`(0,1,1)가 `.post__title`(0,1,0)보다 **강하다.** 클래스 하나로는 여백을 되돌리지 못한다.
  - `::before { display: none }` 이 먹은 것은 `.content h2::before` 에 `display` 선언이 없어 충돌하지 않았기 때문.
  - 해결: `.content .post__title` 로 세기를 맞췄다.
- 원 저자가 `.greeting__title` 에 인라인 `padding-left:0` 을 붙여 둔 것도 같은 함정을 인라인으로 때운 흔적이다.
- 목록 마지막 줄·구분선(`<hr>`)·글 위쪽 테두리가 연달아 그어져 **빈 항목이 둘 있는 것처럼** 보이던 것도 정리.
  `<hr>` 을 걷고 `.post:first-of-type` 에서 위쪽 테두리를 없앴다.

### 5. GitHub Pages 배포 실패 — 브라우저 캐시가 아니었다

- 푸시했는데 검수 주소가 그대로였다. 페리는 시크릿 창 + 쿠키 삭제까지 했는데도 옛 화면.
- 확인해 보니 **레포에는 정상 반영, GitHub 쪽 배포가 실패**하고 있었다.

```
curl -s "https://api.github.com/repos/psw95master/PH-A-7/actions/runs?per_page=3"
```

| 단계 | 결과 |
| --- | --- |
| Build with Jekyll | success |
| **Deploy to GitHub Pages** | **failure** — 시작 4초 만에, 사유 표시 없음 |

- 빈 커밋으로 재트리거해도 같은 지점에서 실패. public·`has_pages: true`·용량 5.3MB·GitHub 전체 장애 없음 —
  전부 정상이라 **콘텐츠 문제가 아니라 배포 잠금**으로 판단했다.
- **해결: 페리가 Settings → Pages 에서 Branch 를 `None` 으로 저장했다가 `main`/(root) 로 되돌림.**
  바로 새 배포가 돌고 성공했다. 이 조작은 저장소 소유자만 할 수 있다.
- 별개로 Pages 는 `cache-control: max-age=600`. 배포가 성공해도 **최대 10분은 옛 파일이 나온다.**
  쿼리스트링 캐시버스터는 무시된다.
- 페리 화면에 로고 자리가 `NH나우하이텍 NAWOO HI-TECH` 로 보인 것은 **HTML 은 옛것, CSS 는 새것**이
  섞인 과도기 상태였다. 서버는 정상이었고 강력 새로고침으로 해결.

### 6. 로고 — 원본에 단독 파일이 없다

- 임시로 CSS 로 그려 둔 원형 `NH` 마크를 현행 사이트 로고로 교체.
- 원본 사이트에 **로고 단독 파일이 없다.** 상단 메뉴 이미지 `images/main/menu.gif`(1000×85) 안에
  로고와 메뉴 글자가 함께 구워져 있다. `footer.gif` 에도 로고는 없다.
- 남색 화소(`b - r > 25`)만으로 경계를 잡아 **192×48** 로 잘라냈다.
  - > ⚠️ 첫 시도는 흰 여백 기준으로 잘라 `202×53` 이었는데, **왼쪽 5px 에 원본 메뉴의 초록 그라디언트
    끝자락이 딸려 왔다.** RGB (245,249,235) 로 아주 옅어 배경 정리 기준(242 초과)에 걸리지 않았다.
    남색 기준으로 다시 잡아 해결.
- 원본이 이 크기뿐이라 **표시 높이를 36px 로 묶었다.** 그보다 키우면 흐려진다.
  고해상도 로고 원본(AI·EPS) 확보를 `PH-B-35/README.md` 6절 확인 항목에 추가.

### 7. 화면에서 걷어낸 내부 메모

- **검토 메모 상자 10개 전부 삭제.** 작업하면서 남긴 `※확인 필요` 점선 상자로, 클라이언트가 볼 화면에
  있을 내용이 아니다. 조직도·연혁·인증현황·설비현황·오시는길·제품·도면·품질방침·공지사항·Q&A.
  - **확인 항목 자체는 `PH-B-35/README.md` 6절에 그대로 있다.** 화면에서만 뺐다.
- **꼬리말 「유지보수 : 아이티포유」 링크 삭제.** 원본에 있던 유지보수사 표기.
  쓰이지 않게 된 `maintainer` 항목과 CSS 도 함께 걷었다.

### 8. 탑 배너 좌우 여백

- 좁은 화면에서 배너 안 글자만 화면 끝에 붙어 있었다.
- 원인: `<div class="wrap hero__inner">` 인데 `.hero__inner { padding: 44px 0 200px }` 가
  **`.wrap` 의 좌우 여백을 0 으로 덮어쓰고 있었다.**
- 데스크톱은 `.wrap` 의 최대폭(1120px) 덕에 가운데 정렬돼 티가 나지 않았다. **모바일에서만 드러나는 종류.**
- 좌우값을 `var(--gutter)` 로 되돌려 로고·본문과 같은 선에 세웠다.

### 9. 연혁

- 항목 앞의 초록 월 숫자(`12.` `08.` `01.`)를 화면에서 걷었다. 쓰이지 않게 된 `.history__month` 와
  두 칸 그리드도 정리. **월 값은 정렬 근거라 데이터에는 남겨 뒀다.**
- 2002년 항목을 **12 → 11 → 10** 으로 뒤집었다. 연도는 최신순인데 연도 안만 오래된 순이라 방향이 어긋나 있었다.
- 2003년은 **건드리지 않았다.** 두 항목 모두 원본에 `01` 로만 적혀 있어 어느 쪽이 먼저인지 알 수 없다.
  근거 없이 뒤집으면 없는 사실을 만드는 셈이다.

## 다음 세션 참고사항

### 화면 검수는 헤드리스 크롬으로

- 크롬 확장은 이 작업에서 두 번 멈췄다. **화면 폭을 바꿔 가며 훑는 검수는 헤드리스 CLI 가 안정적이다.**
- 폭을 지정해 찍을 때는 **반드시 iframe 을 거친다.** `--window-size` 를 그대로 믿으면 잘린 화면을
  버그로 오인한다.
- 넘침 검사는 iframe 안에서 `documentElement.scrollWidth` 와 각 요소의 `getBoundingClientRect().right` 를
  비교하되, **`overflow-x: auto` 조상을 가진 요소는 제외**해야 오탐이 안 난다.
- 검사·촬영용 임시 HTML 은 같은 오리진이어야 해서 레포 안에 둘 수밖에 없다. **작업 끝나면 지울 것.**

### GitHub Pages

- 🔴 **푸시했는데 화면이 그대로면 브라우저 캐시부터 의심하지 말 것.** 빌드가 성공해도 배포만 따로 죽는다.
  `actions/runs` 의 `conclusion` 을 먼저 본다.
- 배포 단계가 사유 없이 몇 초 만에 끊기면 **Settings → Pages 에서 Branch 를 `None` ↔ `main` 으로
  왕복**해야 풀린다. 페리만 할 수 있다.
- 배포 성공 후에도 **CDN 캐시 10분**. 반영 확인은 `curl` 로 실제 문자열을 보는 게 확실하다.

### CSS

- `.content h2` 처럼 **요소를 포함한 선택자는 클래스 하나보다 강하다.** 예외 규칙을 만들 때는
  `.content .post__title` 처럼 스코프를 맞춰야 한다. 인라인 스타일로 때우면 다음 사람이 또 걸린다.
- 그리드 칸 안에 줄바꿈 없는 요소나 `min-width` 가진 표가 들어가면 **`min-width: 0` 이 없는 한 칸이 벌어진다.**

# PH-A-7_260818 (2) — A안 견적서 작성

같은 날 두 번째 세션. 제안서 A안(기능 개편) 기준 견적서를 구글 시트에 A4 가로 1장으로 조판했다.

## 배경 (Why)

- 제안서의 A안이 정해진 뒤 나우하이텍에 보낼 견적서가 필요해졌다.
- 페리가 준 재료는 세 가지 — 제안서 `01-2`(구축비·운영비 비교), `05-1`(견적 요약과 직무별 산출 근거),
  그리고 디자인 참고용 인보이스 이미지 1장(흑백 미니멀, 우측 금액 강조 박스).
- 조건: **A4 가로 1장 출력**, 구글 시트에 작성.

## 과정 (How)

### 1. A4 가로에 맞춘 조판

- A4 가로 인쇄 영역은 **842×595pt**. 기본 여백(0.5in)을 빼면 대략 1,026×698px 이 쓸 수 있는 폭이다.
- 여기에 맞춰 **열 폭 합계 1,005px · 행 높이 합계 605px** 로 설계했다.
- 가로 폭을 살려 **2단 배치** — 좌측 `01. 견적 내역`, 우측 `02. 산출 근거`, 하단 전체폭 `03. 계약 조건`.
- 산출 근거의 `1,208,127 (402,709)` 처럼 괄호 안 1일 단가는 `textFormatRuns` 로 **한 셀 안에서 회색으로만** 흘렸다.
  열을 하나 더 쓰지 않으려는 선택.

### 2. 함정 — `updateCells` 의 `fields` 가 배경색을 지운다

- 2행 우측이 통째로 **검정 바**가 되면서 그 위의 `QUOTATION` 검정 글씨가 묻혀 사라졌다.
- 원인: `fields` 에 `userEnteredFormat` 을 통째로 지정하고, 값 없는 빈 셀에는 `backgroundColor` 를 안 넣었다.
  **Sheets API 에서 배경색 미지정은 흰색이 아니라 `{0,0,0}` = 검정이다.** 앞서 깔아 둔 흰 배경을 덮어썼다.
- 해결: 해당 범위를 흰색으로 되돌렸다. 이후에는 배경만 고칠 때 `fields` 를 `userEnteredFormat.backgroundColor` 로 좁혔다.

### 3. 인쇄 설정은 API 로 저장할 수 없다

- 용지 크기·방향·여백은 **Sheets API v4 가 지원하지 않는다.** 시트에 박아 둘 방법이 없다.
- 그래서 열 폭·행 높이로만 규격을 맞추고, 나머지는 인쇄 대화상자에서 매번 지정해야 한다.
  (A4 · 가로 · 너비에 맞춤 · 여백 기본값)

### 4. 🔴 좌우 여백이 안 맞던 이유 — 인쇄 범위의 끝

- 좌측 여백만 우측의 4배로 붙었다. 좌우 여백용 열을 대칭으로 잡아 뒀는데도.
- 원인: **구글 시트 인쇄 범위는 항상 A열에서 시작해 "값이 있는 마지막 열"에서 끊긴다.**
  좌측 여백 열(`A`·`B`)은 시작점이라 살아남고, 우측 여백 열(`L`·`M`)은 값이 없어 통째로 잘려 나갔다.
- 해결: **`M29` 에 공백 한 칸**을 넣어 인쇄 범위를 M열까지 늘렸다. 화면에는 아무것도 안 보인다.
  - > ⚠️ **`M29` 는 지우면 안 된다.** 지우는 순간 우측 여백이 다시 사라진다.
  - 처음엔 `'` + 공백을 `RAW` 로 넣었다가 **작은따옴표가 그대로 찍혔다.** `RAW` 는 앞의 `'` 를
    이스케이프로 해석하지 않는다. 공백 하나만 넣어 해결.

### 5. 🔴 비사업자는 부가세를 청구할 수 없다

초안은 `공급가액 1,200,000 + 부가세 10% 120,000 = 1,320,000원` 구조였다.
페리가 **"나는 비사업자인데 부가세를 청구하는 게 맞냐"** 고 물어 확인한 결과, **틀린 구조였다.**

- 부가세는 **사업자만 거래징수한다.** 사업자등록이 없으면 세금계산서를 발행할 수 없고,
  받은 부가세를 신고·납부할 창구 자체가 없다.
- 웹사이트 제작은 [부가가치세법 시행령 제42조](https://law.go.kr/%EB%B2%95%EB%A0%B9/%EB%B6%80%EA%B0%80%EA%B0%80%EC%B9%98%EC%84%B8%EB%B2%95%EC%8B%9C%ED%96%89%EB%A0%B9/%EC%A0%9C42%EC%A1%B0)
  의 면세 인적용역(저술·도안·강연·번역 등) 열거 항목에 **없다.**
  그러니 **"면세라서 안 붙인다"가 아니라 "청구할 자격이 없어서 안 붙인다"** 가 정확한 설명이다.
- 대신 지급자(나우하이텍)가 **사업소득 3.3%를 원천징수**하고 나머지를 입금한다.

**검토했다가 버린 대안 (260818 판단)**

| 안 | 버린 이유 |
| --- | --- |
| 총액을 1,240,950원으로 올려 실수령 120만원 맞추기 | 견적 금액이 올라가 상대가 근거를 묻게 된다 |
| 사업자등록 후 부가세 청구 | 매입세액공제가 되니 상대에겐 유리하나, 등록·신고 의무가 따라오고 이번 건 일정에 안 맞는다 |
| 도메인 실비를 구축비와 합쳐 한 합계로 내기 | 1회성 비용과 매년 나가는 비용이 섞여 "얼마를 내야 하나"가 흐려진다 |

> ⚠️ 나우하이텍 입장에서는 **세금계산서를 못 받는 게 불리하다.** 부가세 매입세액공제가 안 된다.
> 협의 중 "세금계산서 발행 되냐"는 질문이 나올 가능성이 높다.

### 6. 도메인 실비를 용역대금에서 분리

- 도메인 연 19,800원을 용역대금에 넣으면 **그 실비에도 3.3%가 붙는다.** 금액은 654원이지만 구조가 틀렸다.
- **고객사가 가비아에 직접 결제**하는 방식으로 돌렸다. 견적서에는 금액 대신 `고객사 직접 결제` 로 적고,
  실비 정보(`가비아 .co.kr · 연 19,800원`)는 내용 칸에 남겼다.

### 7. 결과 검증 방법

매번 눈으로 확인하려고 export URL 로 PDF 를 받아 페이지 수와 용지를 확인하고, 그림으로 렌더해 봤다.

```
https://docs.google.com/spreadsheets/d/{ID}/export?format=pdf&gid=0
  &size=A4&portrait=false&fitw=true&gridlines=false&printtitle=false
  &sheetnames=false&pagenum=UNDEFINED&fzr=false

- PDF 의 `/Count` 로 페이지 수, `/MediaBox` 로 용지 규격을 본다 (`842 595` 면 A4 가로).
- 이 맥에 `poppler` 가 없어 `Read` 의 PDF 렌더가 안 된다. **macOS 기본 `qlmanage` 로 우회**했다.

```

# PH-A-7_260818 (3) — 검수용 진입 게이트와 색인 차단

같은 날 세 번째 세션. 검수 링크가 우연히 퍼지는 것을 막을 형식적 장치를 붙였다.
그 과정에서 **검수본이 검색에 잡힐 수 있는 상태였다는 것**이 드러나 색인 차단까지 함께 넣었다.

---

## 배경 (Why)

- 페리 요청 — 검수 주소 첫 진입 시 4자리 번호(`0000`)를 넣어야 열리게. **"보안 목적이긴 한데 퍼포먼스 형식"** 이라는 전제.
- 게이트를 붙인 뒤 페리가 **"이 홈페이지 검색으로 찾을 수는 없죠?"** 라고 물었다. 확인해 보니 **막는 장치가 하나도 없었다.**

---

## 과정 (How)

### 1. 게이트는 `build.py` 에 넣었다

- 🔴 **HTML 14개는 전부 `build.py` 산출물이다.** 페이지를 직접 고쳤으면 다음 빌드에 통째로 날아간다.
- 모든 페이지가 공유하는 `page()` 셸의 `<head>` 에 `<script src="assets/js/gate.js">` 한 줄을 넣었다. 14개 전부 적용.

### 2. 본문이 한 순간도 비치지 않게

- 게이트가 늦게 뜨면 **잠겨야 할 내용이 잠깐 보였다가 가려진다.** 그러면 장치의 의미가 없다.
- 해결 — `gate.js` 를 `<head>` 에서 **동기 스크립트**로 실행해 `html` 에 `nh-locked` 클래스를 먼저 붙인다.
  `<head>` 의 동기 스크립트는 body 파싱보다 반드시 먼저 실행되므로, 아래 규칙이 body 가 그려지는 순간부터 걸린다.

```css
html.nh-locked { overflow: hidden; }
html.nh-locked body > *:not(.nh-gate) { display: none !important; }
```

- 통과 여부는 `sessionStorage`. **페이지를 옮겨 다닐 때는 다시 묻지 않고, 탭을 닫으면 다시 묻는다.**
- 스토리지가 막힌 환경에서는 게이트를 아예 걸지 않는다. 잠긴 채로 못 여는 상황을 만들지 않으려는 선택.

### 3. 헤드리스 크롬으로 10개 항목 검증

같은 오리진 iframe 안에서 실제로 폼을 제출해 봤다. (260818 (1) 세션의 검증 패턴과 동일)

### 7. Search Console 은 열지 못했다

- 현재 `~/apps/gdocs/token.json` 의 권한은 documents·drive·spreadsheets 뿐. Search Console 호출은 `403 insufficient scopes`.
- 열려면 세 가지가 필요하다 — Cloud Console 에서 **API 활성화**, `auth.py` 권한 추가 후 **페리의 브라우저 재인증**,
  그리고 무엇보다 **그 사이트가 Search Console 에 속성으로 등록돼 있어야 한다.**
- 이번엔 "색인됐나" 하나만 알면 됐으므로 **구글에서 `site:` 로 직접 조회**하는 쪽을 택했다. 5초면 끝난다.
