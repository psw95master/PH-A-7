- 전날(260806) 슬라이드 업로드까지 마쳤으나, 스크립트와 슬라이드가 어긋나 있었고 제안 순서에 구조적 문제가 있었다. [[ESL-D-1_log_260806]]

- 지난 로그에서 막혔던 슬라이드 업로드 문제(맥 파일 선택창)도 이번에 우회 경로를 찾았다.

## 과정 (How)

### 1. 표지 키카피 확정

페리 초안 「웹사이트 리뉴얼을 통한 온라인 내 기업 신뢰도 회복」에서 출발해 **「찾을 수 있는 기업, 믿을 수 있는 기업」**으로 확정했다.

- 「노출」은 한국어에서 **보안 사고**로 먼저 읽힌다. 보안 경고가 핵심 진단인 제안서라 정반대 신호가 되어 제외
- 제목이 이미 「웹사이트 리뉴얼 제안서」라 부제의 「웹사이트 리뉴얼」은 중복
- 명사 7개 연속(기업정보-문제해결-온라인-기업-신뢰도-회복)이라 한 번에 안 읽힘 → 대구 구조로 압축

### 2. S2 「설비·자격·납품 이력」 근거 검증 — 파일에 근거가 없었다

페리 질문으로 확인한 결과 **v2.0에서 작성 과정 중 나온 해석**이었고 조사 기록이 없었다. 웹으로 재검증:

| 주장 | 확인된 근거 |
| --- | --- |
| 자격(인증) | 보쉬 공급업체 품질 요구사항 — 최소 ISO 9001 인증 QMS + SSQA 심사 |
| 설비 | 조선 기자재는 선급 인증 필수, KOLAS Type 3 = 형식시험 + **공장심사** |
| 납품 이력 | 진입 요건이 아니라 **유지·관리 항목**으로 나타남 (1년 이상 실적 없으면 관리 대상) |

- **개별사 등록 기준은 확인 불가** — 포스코는 e-Procurement 내부, 한화오션은 협력사 포털 로그인 뒤
- 「세 가지를 모두 갖춘 곳**만**」이라는 배타 단정은 어떤 문서도 뒷받침하지 않는다 → **「함께 심사받아야」**로 완화
- 발표 멘트의 「선급 승인이 있어야」는 업계 논리로는 맞으나 **나우하이텍 증서가 GL 명의·만료 추정**이라 ISO(2005년 취득·20년 유지)로 교체

### 3. 스크립트 v2.6 — 목차 재구성

페리 제안(진단을 앞으로, 웹사이트란을 뒤로)을 받되, 그대로 옮기면 **질문 → 실패 → 회복** 축이 부러지는 문제가 있었다. S3(세 질문)이 S9(실패)보다 뒤로 가기 때문이다.

**해결 — 진단을 사실과 해석으로 갈랐다.**

| 장 | 내용 | 성격 |
| --- | --- | --- |
| 01 About 나우하이텍 | S2 회사 + S3 진단 요약 + S4·S5·S6 측정값 | **사실만** |
| 02 웹사이트란 | S7 역할 → S8 채용 → **S9 진단 종합** | **해석** |

S9를 02장으로 옮긴 것이 핵심이다. 「위험한 회사로 읽힙니다」 같은 해석 문장을 전부 S9로 모아 01장은 측정값에서 끝나게 했다. 결과적으로 S7(질문) → S9(실패)가 붙어 축이 오히려 촘촘해졌다.

> **장 번호는 v2.6부터 고정한다.** 순서가 바뀌어도 S번호는 유지하고 순서는 목차로 관리한다. 슬라이드·피그마 프레임 이름이 매번 밀리는 것을 막기 위함이다.

파일: `ESL-C-10/ESL-C-10. 나우하이텍 웹사이트 리뉴얼 제안서_v2.6_260806.md` (v2.5→v2.6 번호 대조표 포함)

### 4. HP 디자인 스킬 도입

`npx getdesign@latest add <이름>` — DESIGN.md 템플릿을 받는 CLI. 받은 파일은 **iCloud `02. ai skill/<이름>/DESIGN.md`** 에 보관한다(하위 폴더로 나눠야 파일명 충돌 없음).

- `dell-1996` — 90년대 카탈로그 톤. 나우하이텍 제안서에는 부적합(「낡은 사이트」 지적과 모순)
- `hp` — 흰 바탕 · 잉크 · 파랑 하나. **이쪽을 채택**

적용 규칙: 파랑은 CTA·링크·셰브론에만 화면당 2회까지 / 카드 16px · 버튼 4px / 깊이는 그림자가 아니라 면 대비 / 잉크 슬래브로 리듬을 닫는다.

### 5. 구글 슬라이드 업로드 — 막힌 길이 뚫렸다

> ⚠️ 260806 로그의 「업로드는 반드시 맥 파일 선택창을 거친다」는 **브라우저 조작 경로에 한정된 이야기다.** API 경로에는 해당하지 않는다.

**슬라이드 API는 여전히 잠겨 있다** (프로젝트 37189686021에서 `slides.googleapis.com` 비활성, SERVICE_DISABLED). 페리가 콘솔에서 켜지 않아도 되도록 우회했다.

```python
# 드라이브 API로 업로드하면서 변환하면 네이티브 구글 슬라이드가 된다
meta = {"name": ..., "parents": [FOLDER],
        "mimeType": "application/vnd.google-apps.presentation"}
drive.files().create(body=meta, media_body=MediaFileUpload(PPTX, mimetype=PPTX_MIME))
```

- 토큰은 `~/apps/gdocs/token.json` 재사용 (drive 스코프가 슬라이드 변환까지 커버)
- 수정은 `files().update(fileId=...)` — **같은 링크에 덮어쓰기**되어 새 파일이 생기지 않는다

## 다음 세션 참고사항

- ⚠️ **슬라이드를 직접 편집한 뒤 재빌드하면 그 수정이 덮인다.** 빌드 스크립트가 매번 전체를 새로 만들어 같은 파일에 씌우기 때문이다. 손댈 일이 생기면 **수동 수정분을 먼저 스크립트에 반영**하고 빌드할 것.
- 빌드·업로드 명령 (venv는 `~/apps/gdocs/venv` 재사용, python-pptx 1.0.2 설치돼 있음)

```bash
~/apps/gdocs/venv/bin/python build_v27.py   # PPTX 생성
~/apps/gdocs/venv/bin/python update.py      # 같은 구글 슬라이드에 덮어쓰기
```

- **슬라이드 API는 아직 꺼져 있다.** 켜려면 콘솔에서 `slides.googleapis.com` 사용 설정(프로젝트 37189686021). 지금은 드라이브 변환으로 우회 중이라 급하지 않다.
  - > ⚠️ **260815에 무효가 됨** — Slides API 가 정상 호출된다. `~/apps/gdocs/token.json` 의 `drive` 스코프로 `build("slides","v1")` 이 그대로 통과한다. 이후 작업은 PPTX 변환이 아니라 Slides API 직접 호출로 진행했다. [[PH-A-7_@log_260817]]
- 옵시디언 볼트 파일명은 **NFD 정규화**라, 페리 메시지에서 복사한 경로(NFC)로 `Read`하면 「없는 파일」이 된다. `ls`·`find`로 실제 경로를 받아 쓸 것.
- 「회사」와 「기업」이 섞여 있다. 표지 키카피는 **기업**, 스크립트 본문은 **회사**. 통일 여부 미결.
