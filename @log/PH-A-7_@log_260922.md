## 2. 타이틀 규칙 — 영문만 남기고 한글은 팝업으로

페리 확정 사항이다.

1. **타이틀에는 영문만** 남긴다.
2. **한글은 사진을 눌렀을 때 팝업에서** 보여준다. 한글이 없으면 없는 대로 둔다.
3. **같은 타이틀이 여럿이면 뒤에 `(1) (2) …`** 를 붙인다.
4. 없어지는 기존 타이틀은 **엑셀에 보관**한다.

### 구현

- 한글과 규격을 목록에 두지 않고 `<figure>` 의 `data-ko` / `data-spec` 에 실었다.
  `lightbox.js` 가 읽어 팝업 설명줄에 「한글 · 규격」으로 합쳐 보여준다.
- **목록 화면에는 한글이 한 글자도 남지 않는다.** 규격 줄도 뺐다(`1017ae0`).
- 🔴 **영문 이름이 없는 설비 4칸은 기존 한글 타이틀을 그대로 뒀다.**
  빈 칸이 생기는 것을 막기 위한 임시 조치다.

## 4. 화면이 길어진 문제 — 두 번 고쳤다

사진이 14장에서 50장으로 늘자 유압장치 페이지가 `3,424px` → `9,650px` 가 됐다.

### 1차: 하단 번호 리모컨 (`1aeb0d8`) → 폐기

- 한 쪽에 10칸씩 끊고 아래에 `‹ 1 2 ›` 를 달았다.
- 숨긴 칸은 `data-lightbox` 를 떼어 팝업 목록에서도 빠지게 했다.
- **페리 판단으로 폐기.** 목록은 예전처럼 쭉 이어지는 편이 낫다고 결정.

### 2차: 오른쪽 목차 (`35fe576` → `aebfb52`) — 확정

- 노션 방식이다. 평소에는 **짧은 선만** 서 있고, 마우스를 올리면 목차가 펼쳐진다.
- 지금 보고 있는 자리의 선은 **초록으로 길어진다**.
- 같은 타이틀은 한 줄로 묶고 오른쪽에 장수를 적는다. **유압장치 50칸이 26줄, 설비현황 17칸이 11줄**.
- 목차가 스크롤돼도 제목(「유압장치 및 부품」/「설비현황」)은 위에 남는다.
- 🔴 **처음에 `1500px` 이상에서만 띄웠더니 페리 화면(배율 100%)에서 안 보였다.**
  접힌 폭이 좁은 것을 살려 `1180px` 으로 낮췄다. 마우스가 없는 기기는 `hover: hover` 로 걸러 낸다.

## 2. 🔴 전환 직후 사이트 다운 — 이번 세션의 사고

전파가 끝나자마자 **옛 사이트도 새 사이트도 아닌 오류 화면**이 떴다.

```
http://nawoohitech.co.kr   → 409 (Cloudflare)
https://nawoohitech.co.kr  → 연결 불가 (인증서 없음)
nawoohitech.pages.dev      → 200 정상
```

### 원인

Pages 커스텀 도메인 2건이 `비활성화됨 (DNS 설정 필요)` 상태였다.
DNS 레코드는 멀쩡했는데(apex·www 둘 다 `nawoohitech.pages.dev` 로 proxied),
**Cloudflare 가 이 Zone 의 소유 확인을 아직 안 끝낸 상태**였던 것이 진짜 원인이다.

Pages 도메인 추가 화면이 이렇게 말해줘서 알았다 —
「페이지 프로젝트에 추가하기 전에 DNS 를 Cloudflare 로 이전해야 합니다」.

### 조치 순서

1. **www 재검증** (`Check DNS records`) → 1~2분 만에 `활동적인` + SSL 발급. **www 는 이때 살아났다**
2. **apex 는 재검증으로 안 풀려** 커스텀 도메인을 지우고 다시 추가하려 했으나,
   Zone 이 `pending` 이라 추가 자체가 막혔다
3. Zone 개요에서 **「지금 네임서버를 확인하세요」** 를 눌러 소유 확인을 재촉했다
4. 확인이 끝날 때까지 apex 접속자가 오류를 보는 것을 막기 위해 **임시 전달 규칙**을 걸었다
5. 약 30분 뒤 Zone 이 확정되어 apex 를 Pages 에 정식 등록 → 인증서 발급 → **임시 규칙 제거**

### 임시로 걸었다 지운 것 (기록용)

```
리디렉션 규칙  http://nawoohitech.co.kr/*  →  https://www.nawoohitech.co.kr/${1}
상태 코드 302 (임시) · 쿼리 문자열 유지
```

**302(임시)를 쓴 것이 핵심이다.** 301(영구)로 걸었다면 브라우저와 검색엔진이 영구 캐시해서,
규칙을 지운 뒤에도 한동안 www 로 끌려갔을 것이다.
규칙 이름에도 `temporary 260922 - remove after zone active` 를 적어 제거 조건을 남겼다.

`wget` 이 없는 환경이라 표준 라이브러리만으로 20여 줄짜리 재귀 수집기를 썼다.
HTML·이미지·CSS·JS·PDF·게시판까지 전부 들어 있다.
못 받은 4건(`music.htm`, `mEmbed.js`, 배경 이미지 2장)은 **옛 사이트 자체의 깨진 링크**다.

## 5. 「아직 옛날 사이트가 나온다」 — 캐시 문의 대응

전환 직후 페리 기기에서 옛 사이트가 계속 떴다. **시크릿 모드에서도 같았다.**

브라우저 캐시가 아니라 **기기(OS) 의 DNS 캐시**였다. 옛 A 레코드의 TTL 이 `86400`(24시간)이라
그만큼 남아 있었고, 이 층위는 시크릿 모드가 우회하지 못한다.

진단의 결정적 단서는 **주소창이 www 로 넘어가지 않은 것**이었다.
당시 걸어둔 전달 규칙은 Cloudflare 에 도착해야 작동하는데, 넘어가지 않았다는 것은
Cloudflare 까지 가지도 않고 캐시된 옛 IP 로 직행했다는 뜻이다.

```
sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder
chrome://net-internals/#dns  →  Clear host cache
```

페리가 모바일·PC 양쪽에서 전환을 확인했다 (`260922`).

> **전 직원에게 캐시 삭제를 시킬 필요는 없다.** TTL 이 만료되면 저절로 풀린다.
> 최대 24시간, 재부팅하면 즉시. 처음 방문하는 사람에게는 처음부터 새 사이트가 보인다.
> 회사 안내가 필요하면 「컴퓨터를 껐다 켜기」 한 줄이면 충분하다.

## 🔴 미해결 — 로그 등록 후 발생 (`260922 21:23`)

위 「전환 완료」 보고 직후, **페리 PC 에서 `https://nawoohitech.co.kr` 이 403 Forbidden 을 띄웠다.**
전환이 깨진 것이 아니라 **그 PC 만 옛 서버에 닿고 있는 상태**다.

### 확인된 사실

| 확인 경로 | 결과 |
| --- | --- |
| Cloudflare 두 IP 직접 (`104.21.47.243` · `172.67.174.142`) | ✅ 200, 새 사이트 |
| 공개 DNS (`1.1.1.1` · `8.8.8.8`) | ✅ Cloudflare IP 응답 |
| 네임서버 | ✅ `celine` / `garret` |
| 페리 **휴대폰 (LTE)** | ✅ 정상 |
| 페리 **PC (크롬)** | ❌ 403 Forbidden |

증상이 옛 서버와 정확히 일치한다. 옛 서버에 직접 https 로 들어가면 같은 화면이 나온다.

```
403 Forbidden — You don't have permission to access / on this server.   (Apache)
인증서 CN = jegikorea.com   (2023-10-17 만료)
```

주소창의 「주의 요함」과 `https` 취소선도 이 만료 인증서 때문이다.

### 🔴 단순 TTL 만료 대기로 설명되지 않는다

**같은 PC 에서 한 번 정상 확인이 됐다가 다시 옛 서버로 돌아갔다.**
캐시가 자연히 풀리는 방향과 반대다. 그래서 「24시간이면 저절로 풀린다」는 설명은
이 건에 대해서는 **철회한다.** 원인을 따로 잡아야 한다.

후보는 둘이다. 어느 쪽이냐에 따라 대책이 완전히 갈린다.

1. **기기/네트워크의 이름 조회가 옛 값에 묶임** → `dig` 가 `211.51.221.181` 을 준다
2. **크롬 내부 문제** (자체 DNS·HTTPS 자동 전환·소켓 재사용) → `dig` 는 정상인데 크롬만 옛 서버로 간다

### 다음 세션이 가장 먼저 할 일

PC 를 켜고 **브라우저를 열기 전에** 실행한다. 추측하지 말고 이 결과부터 볼 것.

```
dig nawoohitech.co.kr +short
nslookup nawoohitech.co.kr
```

타당한 요구다. 다만 정직하게 적어둔다 —
**기기에 저장된 주소 정보는 서버 쪽에서 강제로 지울 수 없다.**
