## 2. 크게 보기 팝업 (`assets/js/lightbox.js`)

사진을 누르면 검은 막이 덮이며 크게 열린다. 사진 아래에 제품명과 설명이 함께 나온다.

- **제목·설명을 따로 적어 두지 않는다.** 목록의 `figcaption` / `.tile__meta` 를 그대로 읽는다.
  두 벌이 되면 반드시 어긋나기 때문이다.
- 좌우 버튼과 키보드 `←` `→` 로 이동, 현재 위치를 `n / 14` 로 표시
- 닫기 버튼 · `ESC` · 검은 배경 클릭 셋 다로 닫힌다
- 누를 자리이므로 `span` 이 아니라 **`button` 으로 감쌌다.** 닫으면 눌렀던 사진으로 포커스가 돌아간다
- 팝업이 떠 있는 동안 뒤 화면 스크롤을 잠근다

## 5. 캐시 사고 2건 — 검수 화면이 뒤섞였다

이날 같은 뿌리의 문제를 두 번 겪었다. **둘 다 서버는 멀쩡했다.**

### 5-1. 없어진 주소로 들어가 404

인재 채용에 들렀다가 다른 페이지로 가면 메뉴가 공지사항으로 보이고, 누르면 404 가 떴다.
배포본 14개를 전부 훑어 `notice.html` 참조가 0건인 것을 확인했다.

**대응** — 예전 주소를 지우는 대신 새 주소로 넘긴다.
`build_moved()` 가 `meta refresh` + `canonical` 을 담은 페이지를 만든다.
밖으로 이미 공유된 링크가 있어도 함께 살아난다. sitemap 에는 넣지 않는다.

> 앞으로 페이지 주소를 바꿀 때는 `MOVED` 에 한 줄 추가하면 된다.

### 5-2. 페이지마다 시점이 뒤섞임

품질방침·사업분야 화면에서만 여전히 옛 메뉴가 보였다.
두 페이지의 배포본을 직접 받아 "인재 채용"만 들어 있는 것을 ETag·age 까지 대조해 확인했다.

**원인** — GitHub Pages 는 HTML 을 10분 캐시하고(`max-age=600`),
`Cmd+Shift+R` 은 **그때 보고 있는 페이지 하나에만** 먹는다.
그래서 검수하며 둘러본 페이지마다 시점이 달라진다.
자산에 붙인 `?v=` 표식은 HTML 자체에는 쓸 수 없어 이 경우를 못 막았다.

**대응** — 검수 모드에서만 페이지 사이 링크에 빌드 시각을 붙인다.

```html
<a href="quality.html?b=260821024316">품질방침</a>
```

매 빌드마다 주소가 새것이 되므로 캐시된 옛 페이지를 쓸 수 없다.
**라이브에서는 붙지 않는다** — 주소는 깨끗해야 하고 검색엔진에도 불필요하다.
`canonical`·`og:url` 은 절대주소라 손대지 않으며 sitemap 에도 섞이지 않는다.
양쪽 모드로 빌드해 확인 — 검수 32개, 라이브 0개.

> ⚠️ 근본 원인인 10분 캐시는 GitHub Pages 가 정한 값이라 우리가 못 바꾼다.
> Cloudflare 로 옮기면 캐시 헤더를 직접 정할 수 있다.

## 7. 모바일 GNB — 아코디언

좁은 화면에서 하위 메뉴가 전부 펼쳐진 채라 메뉴가 길게 늘어졌다.
대분류를 누르면 그 갈래만 펼쳐지고 나머지는 접힌다. **한 번에 하나만 연다.**

- 대분류는 원래 첫 하위 페이지로 가는 링크다. **좁은 화면에서만** 이동을 막고 펼치는 역할로 바꾼다.
  스크립트가 죽어도 링크로서는 그대로 동작한다
- 보고 있는 페이지가 속한 갈래는 처음부터 펼쳐 둔다
- 넓은 화면으로 넘어가면 펼침 상태를 지운다. 남아 있으면 마우스 오버 드롭다운과 겹친다
- 화살표는 글자가 아니라 테두리로 그렸고, 펼치면 180도 돌아간다

## 8. 모바일 LNB — 화면 전환 없이 넘기기

탭을 누르면 페이지가 통째로 다시 열려 화면이 깜빡이고 스크롤이 튀었다.
세 안을 놓고 페리가 **A안**을 골랐다. `260821 확정`

| 안 | 방식 | 판단 |
| --- | --- | --- |
| **A** | **누른 페이지의 본문만 가져와 끼워 넣기** | **채택** |
| B | 같은 갈래를 한 페이지에 다 담고 탭으로 보이기 | 인사말·연혁이 각자의 주소를 잃는다. 이번 프로젝트의 SEO 목표와 정면으로 어긋나 기각 |
| C | 지금처럼 두기 | 요청한 효과가 없다 |

A안은 주소를 그대로 바꾸므로(`history.pushState`) 공유·북마크·뒤로가기가 살아 있고
검색엔진은 여전히 페이지마다 따로 본다.

**갈아끼우는 것** — 본문, 페이지 제목, 이동 경로, 문서 제목, description, 탭 표시.
본문이 오는 동안 흐려져 눌린 것이 보인다. 가져오기에 실패하면 그냥 페이지를 연다.

> **함정** — 본문을 `innerHTML` 로 넣으면 그 안의 `<script>` 도 DOM 에 들어간다.
> 실행되지도 않으면서 "이미 로드됨"으로 잡혀, 도면소개 → 유압장치로 넘어갔을 때
> 팝업 스크립트를 안 불러왔다. 넣기 전에 script 를 떼도록 고쳤다.
> `lightbox.js` 는 `window.NH_lightbox` 로 열어 두어 본문이 바뀔 때마다 다시 훑게 했다.

### 스와이프 — 넣었다 걷어냄

### LNB 붙박이

대신 탭 줄을 머리말 바로 아래에 고정했다. 본문을 내려 읽는 동안에도
지금 어느 항목인지 보이고, 옆 항목으로 바로 옮겨 갈 수 있다.

> **함정** — `.layout` 이 grid 인 채로는 `sticky` 가 먹지 않는다.
> 좁은 화면에서는 메뉴와 본문이 각각 다른 칸에 놓이는데, 메뉴 칸의 높이가
> 메뉴 높이와 같아 **움직일 범위가 0** 이 된다. 처음엔 이걸 모르고 sticky 만 걸었다가
> 메뉴가 그대로 위로 사라졌다. 좁은 화면에서는 `block` 으로 되돌리고
> grid 는 900px 이상에서만 쓰도록 옮겨 해결했다.

마무리로 두 가지를 더 잡았다.

- 머리말 높이가 111px 이라 `top` 도 111px 로 맞췄더니 소수점 반올림 탓에 1~2px 틈이 생기고
  그 사이로 본문이 지나갔다. **110px 로 잡아 1px 겹치게** 했다 (실측 −0.75px)

| 차수 | 내용 |
