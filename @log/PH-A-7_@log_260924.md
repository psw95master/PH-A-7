# PH-A-7_260924 — 메일 DNS 정리 · SPF 를 사칭 차단용으로 교체

`260923` 로그의 「다음 세션이 할 일 **1번**」을 처리했다.
옛 호스팅 해지(`260927`)를 **사흘 앞두고** 페리 요청으로 앞당겨 실행했다.

**DNS 에서 옛 서버를 가리키는 것이 하나도 남지 않았다.**
이로써 `260927` 에 호스팅이 해지돼도 이 사이트에는 아무 일도 일어나지 않는다.

작업 중 **삭제 대상을 잘못 고른 구간**이 있었다. 실행 직전에 발견해 사고로 이어지지 않았으나,
같은 함정이 반복될 수 있어 3번에 따로 적는다.

## 배경 (Why)

- `260922` 에 도메인이 Cloudflare 로 넘어왔을 때, 메일 관련 레코드는 **원본 그대로 옮겨 심었다.**
  「끊기면 조용히 끊기는 종류」라서 일단 살려둔 것이다.
- 웹은 이미 Pages 로 가므로 옛 서버는 경로에서 빠져 있었지만, **메일 쪽 3개만 옛 서버를 계속 가리켰다.**
- 해지되면 그 IP 는 **다른 회사에 재할당된다.** 그런데 우리 SPF 에는
  「이 IP 에서 온 메일은 나우하이텍이 맞다」고 적혀 있었다. 그대로 두면 **남의 서버가
  우리 도메인 발신자로 인정받는다.**

### 왜 해지 전에 했는가

페리 요청(`260924`). 사흘 일찍 끊는 셈이라 **먼저 실사용 여부를 확인**하고 진행했다.

## 2. SPF 는 지우지 않고 `v=spf1 -all` 로 바꿨다

요청은 「3개 삭제」였으나, **SPF 만은 지우는 것보다 바꾸는 편이 낫다**고 판단해 먼저 제안했다.

| 방법 | 남는 상태 | 결과 |
| --- | --- | --- |
| 그냥 지우기 | 문패 없음 | 판단 근거가 사라져 **누구나 이 도메인을 사칭해도 안 걸러진다** |
| **`v=spf1 -all` 로 교체** | 「여기선 메일을 보내지 않는다」 | 사칭 메일이 **수신 단계에서 차단**된다 |

메일을 쓰지 않는 도메인의 **표준 권장 설정**이 후자다.
Cloudflare 대시보드도 같은 맥락의 권장사항(`가짜 이메일을 차단하세요`)을 띄우고 있었다.

**페리가 교체안 선택** (`260924` 확정). DMARC 까지 추가하는 안은 과잉으로 보고 넘어갔다.

레코드에 코멘트를 남겼다 — `메일 미사용 선언. 도메인 사칭 메일 차단용 (260924)`

## 3. 🔴 사고 (미수) — 체크박스 일괄 선택이 엉뚱한 줄을 찍었다

지울 3개를 체크박스로 한 번에 고르려 했다. **첫 칸을 체크한 순간 목록 위에 툴바가 생기면서
모든 행이 아래로 밀렸고**, 좌표로 찍은 두 번째·세 번째 클릭이 한 줄씩 어긋났다.

실행 직전 화면은 이랬다.

```
✅ mail A                 ← 맞음
✅ www CNAME              ← 🔴 사이트가 뜨는 주소
✅ TXT (서치콘솔 인증)     ← 🔴 260923 에 등록한 인증
❌ MX                     ← 지워야 할 것이 빠짐
❌ SPF TXT                ← 지워야 할 것이 빠짐
```

**삭제 버튼은 누르지 않았다.** 누르기 전에 화면을 확인하는 단계에서 발견해 전부 해제했다.
눌렀다면 `www` 주소가 죽고 서치콘솔 소유권 인증이 풀렸다.

### 겹친 원인 둘

1. **툴바 삽입으로 행이 밀린다.** 첫 선택 전후로 좌표계가 달라진다.
2. **화면이 한글로 자동번역되면서 버튼 위치까지 움직인다.** 같은 버튼이 매번 다른 자리에 있었다.
   (`260922` 로그의 「대시보드 한글 자동번역 주의」와 같은 함정)

### 🔴 재발 방지 규칙

> **Cloudflare DNS 에서는 좌표로 체크박스를 찍지 않는다.**
> **한 건씩 열어(`Edit`) 폼의 내용을 확인하고 지운다.**
> 삭제 확인창에 뜨는 `Type / Name / Content` 를 매번 대조한다.

이후 세 건 모두 이 방식으로 처리했다. 버튼은 좌표 대신 **요소를 직접 지목**해 눌렀다.
