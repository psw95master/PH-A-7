260821 로그 이후 약 3주 만의 세션. `260913` 에 "이관이 제대로 됐는지 확인해달라"로 시작해

## 2. 🔴 HTTPS 3년 장애 — 이번 세션 최대 발견

작업 중 페리가 "구글에서 검색해 들어가려는데 안 들어가진다"고 했다.
처음엔 우리 작업 때문이 아닌지 의심했으나, 조사 결과 **3년 묵은 문제**였다.

```
http://nawoohitech.co.kr   → 200 정상
https://nawoohitech.co.kr  → 인증서 오류로 차단
```

인증서를 열어보니 두 가지가 동시에 틀려 있었다.

| 항목 | 값 | 문제 |
| --- | --- | --- |
| 만료일 | 2023-10-17 | 약 3년 전 만료 |
| 인증서 주체 | `jegikorea.com` | 나우하이텍 도메인용이 아님 |

**`nawoohitech.co.kr` 용 인증서가 애초에 설치된 적이 없다.**
공용 호스팅이라 같은 서버에 얹힌 다른 고객사 인증서가 대신 응답하고 있었다.

근거를 하나 더 잡았다. **crt.sh 인증서 발급 이력이 0건**이다.
2018년 이후 모든 공개 CA 발급은 Certificate Transparency 로그에 남는데, 기록 자체가 없다.
즉 이 도메인은 HTTPS 인증서를 **한 번도 가진 적이 없다.**

> **왜 "예전엔 됐는데" 인가**
> 됐다. `http://` 로 들어가면 지금도 열린다.
> 바뀐 것은 사이트가 아니라 들어가는 경로다. 크롬과 구글 검색이 `https://` 로 먼저 붙으면서
> 원래부터 잠겨 있던 문으로만 안내되기 시작한 것이다.

### 영향

- 최소 2023년 10월부터 검색으로 유입되려던 방문자 대부분이 보안 경고에 막혔다.
- 구글은 인증서 오류가 있는 사이트를 검색 순위에서 내린다.
- 리뉴얼 효과를 회사에 설명할 때 근거로 쓸 수 있다. **페리가 회사에 공유하기로 함.**

네임서버만 넘기면 Cloudflare 가 정식 인증서를 자동 발급하므로 같이 해결된다.

## 3. Cloudflare 구축 — 전부 완료

페리가 `psw95master` 명의로 계정을 만들고 Global API Key 를 넘겨, 대시보드 작업 없이 API 로 처리했다.

| 항목 | 결과 |
| --- | --- |
| Zone `nawoohitech.co.kr` | 추가 완료. 상태 `pending` (네임서버 변경 전까지 정상) |
| 발급 네임서버 | `celine.ns.cloudflare.com` / `garret.ns.cloudflare.com` |
| Pages 프로젝트 | `nawoohitech` → `nawoohitech.pages.dev` |
| GitHub 연동 | `psw95master/PH-A-7`, output directory `PH-B-35`, 빌드 명령 없음 |
| 자동 배포 | 작동 확인. `main` 에 푸시하면 자동으로 올라간다 |
| 커스텀 도메인 | `nawoohitech.co.kr`, `www` 등록 (`pending`) |

| Always Use HTTPS | **켬** — 구글에 색인된 `http://` 주소로 들어와도 `https://` 로 넘어간다 |

### DNS 레코드 5건

자동 스캔이 기존 레코드를 하나도 못 가져왔다(상대 네임서버가 조회에 응답하지 않음).
whois·dig 로 확인한 원본을 손으로 채웠다.

```
CNAME  nawoohitech.co.kr  → nawoohitech.pages.dev          (새 사이트, proxied)
CNAME  www                → nawoohitech.pages.dev          (새 사이트, proxied)
MX     nawoohitech.co.kr  → mail.itforu.co.kr  우선순위 10   (기존 유지)
TXT    nawoohitech.co.kr  → v=spf1 ip4:211.51.221.181 ~all  (기존 유지)
A      mail               → 211.51.221.181                 (기존 유지)
```

**메일 3건은 현재 설정 그대로 옮겨 심었다.** 네임서버를 넘겨도 메일은 끊기지 않는다.

> 도메인 메일은 실사용하지 않는 것으로 확인됐다. 근거 셋 — 회사 커뮤니케이션은 네이버 주소를 쓴다,
> 현행 사이트 14개 페이지 어디에도 도메인 메일이 없다, SPF 가 웹서버 발송 전용 설정이다.
> 그럼에도 옮겨 심은 이유는 **끊기면 조용히 끊기는 종류**여서다. 비용은 0이다.

## 4. 사이트 수정 3건

### canonical·sitemap 에서 `.html` 제거 (`bfc7acb`)

Cloudflare Pages 는 `/greeting.html` 을 `/greeting` 으로 308 넘긴다. **끄는 설정이 없다.**

canonical 이 `.html` 을 가리키면 정본으로 선언한 주소가 스스로 넘어가는 주소가 되어
검색엔진이 그 선언을 무시할 수 있다. sitemap 13개 주소도 전부 308 을 한 번씩 타고 있었다.

`canonical_url()` 한 곳만 고치면 canonical 태그·sitemap·JSON-LD breadcrumb·리다이렉트 페이지가
같이 따라온다.

### 라이브 모드 전환 (`d2b0911`)

`LIVE = True`. 패스워드 게이트를 빼고 검색엔진을 열었다. sitemap `lastmod` 도 올렸다.

**네임서버 교체 전에 미리 전환했다.** 교체 순간 방문자가 비밀번호 창을 보는 구간을 없애기 위해서다.
그동안 `nawoohitech.pages.dev` 가 공개로 열리지만, canonical 이 전부 실제 도메인을 가리켜
색인은 그쪽으로 모인다.

### 옛 주소 리다이렉트 (`ab0d307`)

구글에는 아직 2006년식 frameset 주소가 색인돼 있다. 그대로 두면 전부 404 가 된다.

```
/main/*     /  301
/bbs/*      /  301
/music.htm  /  301
/css/*      /  301
```

전부 시험 통과했다. 새 사이트는 `assets/css` 를 쓰므로 `/css/*` 와 충돌하지 않는다.

증빙으로 사업자등록증·가족관계증명서·주민등록등본·이메일 이력 4건을 첨부했다.
진행자가 대표의 아들이라는 관계도 함께 적었다.
