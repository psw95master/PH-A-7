## 1. SEO 기초 세팅

### 하기 전 상태

`title` 과 `description` 은 14개 페이지에 이미 개별 작성돼 있었고 `lang="ko"`·시맨틱 마크업·이미지 `alt` 도 잡혀 있었다.
없던 것은 `canonical`, Open Graph, 구조화 데이터, `robots.txt`, `sitemap.xml` 이다.

### 넣은 것 — 전부 `build.py` 안에서 생성된다

| 항목 | 내용 |
| --- | --- |
| `canonical` | 대표 주소를 `https://nawoohitech.co.kr/` 루트 기준으로 통일. 홈은 파일명을 떼고 `/` 로 |
| Open Graph / Twitter Card | 카톡·슬랙 공유 시 미리보기. 이미지는 사옥 전경 |
| JSON-LD | 홈에 `Organization` + `WebSite`, 서브 12개 페이지에 `BreadcrumbList` |
| `robots.txt` | AI 검색 크롤러 7종을 이름으로 명시 허용 |
| `sitemap.xml` | 13개 페이지. 404 는 제외하고 홈부터 우선순위 부여 |
| 소유확인 자리 | `VERIFY_GOOGLE` / `VERIFY_NAVER`. 값이 비면 메타태그를 아예 만들지 않는다 |

- **`Organization` 에 힘을 줬다.** 상호·대표자·설립연월·주소·전화·사업자번호와 `knowsAbout` 9종을 넣었다.
  나우하이텍 니즈 중 "AI 에서 검색 시 링크 제공"이 이 블록에 달려 있다.
  AI 가 "나우하이텍이 무슨 회사인지"를 읽어가는 근거다.
- **전화번호 함정** — 화면에는 `+82-51-831-9161~2` 로 쓰지만 구조화 데이터는 번호 하나만 받는다.
  `~2` 가 붙으면 기계가 못 읽으므로 `split("~")[0]` 으로 대표번호만 넣는다.

### LIVE 스위치

검수 중에는 검색에 잡히면 안 되고, 오픈일에는 열려야 한다. 값 하나로 갈리게 했다.

```python
LIVE = False   # 검수 모드
LIVE = True    # 라이브 모드
```

| | `LIVE = False` (지금) | `LIVE = True` |
| --- | --- | --- |
| robots 메타 | `noindex, nofollow` | `index, follow, max-image-preview:large` |
| `gate.js` | 붙는다 (패스워드 게이트) | 빠진다 |
| `robots.txt` | `Disallow: /` | 전체 허용 + Sitemap 주소 |

> **오픈일에 할 일은 이 값을 `True` 로 바꾸고 `python3 build.py` 를 다시 돌리는 것뿐이다.**
> 404 는 라이브에서도 항상 `noindex` 다.

양쪽 모드로 다 돌려 출력이 갈리는 것까지 확인했다.

### ⚠️ 지금 Pages 주소에서는 `robots.txt` 가 동작하지 않는다

두 파일은 주소 맨 위(`도메인/robots.txt`)에 있어야 인식된다.
검수 주소는 `psw95master.github.io/PH-A-7/PH-B-35/` 안쪽이라 인식 대상이 아니다.
**Cloudflare 에 도메인을 붙이면 자동으로 해결된다. 지금 고칠 것은 없다.**

## 2. 도메인 이관 — 진행 중

- 도메인 등록기관은 **가비아**, 현재 명의는 **아이티포원**(제작사)이다. 나우하이텍 명의가 아니다.

   등록기관이 어디든 Cloudflare Pages 는 붙는다.

### 검색엔진 등록은 도메인이 넘어와야 시작된다

구글과 네이버의 조건이 다르다.

| | 확인 방식 | 가능 시점 |
| --- | --- | --- |
| 구글 서치콘솔 | DNS TXT 레코드 지원 | 도메인만 Cloudflare 에 붙으면 **사이트 배포 전에도** 등록된다 |
| 네이버 서치어드바이저 | HTML 메타태그 / 파일 업로드만 | **새 사이트가 실제로 떠 있어야** 통과한다 |

그래서 순서는 이렇게 된다.

> 도메인 인계 → Cloudflare 연결 → **구글 등록** → 새 사이트 배포(`LIVE = True`) → **네이버 등록** → sitemap 제출

SEO 가 "완료"되는 시점은 마지막 sitemap 제출이다.

### ⚠️ 네임서버를 바꾸면 현행 사이트가 끊긴다

보관처를 바꾸면 새 DNS 는 백지 상태로 시작한다.
도메인 메일을 안 쓰는 것이 확인돼 지킬 것이 사실상 없지만,
**계정을 넘겨받은 직후 가비아 DNS 관리 화면을 캡처해 두기로 했다.** 되돌릴 근거가 필요하다.

## 3. 홈 키배너 — 사진 5장 자동 롤링

### 사진

페리가 드라이브로 전달. `~/apps/gdocs/` 의 Drive 권한으로 받아 웹용 JPEG(82%)로 변환했다.

> **함정** — 드라이브 파일을 `drive.google.com/uc?export=download` 로 직접 받으면
> 이미지가 아니라 로그인 페이지 HTML(884K)이 떨어진다. MCP 나 인증된 API 로 받아야 한다.

원본 PNG 는 장당 2.1~2.7MB. 그대로 뒀으면 배너만 12MB였다. 변환 후 합계 약 2.3MB.

### 구조

- 배너 문구는 **HTML 텍스트 그대로 사진 위에 얹었다.** 사진에 글자를 굽지 않는다는 이 프로젝트의 전제를 따른다.
  (현행 사이트의 문제가 바로 "이미지 안의 글자"였다.)
  가독성 확보용으로 어두운 막 `.hero__scrim` 을 사진과 글자 사이에 깐다.
- 위치 표시 점은 **색만이 아니라 폭도 함께 바뀐다.** `DESIGN.md` 03-2.
- OS "동작 줄이기" 설정이 켜져 있으면 자동 롤링을 하지 않는다. 점으로 직접 넘기는 것은 된다.

### `--hero-focus` — 사진마다 남길 높이

가로로 긴 배너에 16:9 사진을 채우면 위아래가 잘린다. 가운데를 기준으로 잡았더니
**1번(사옥)의 "나우하이텍" 간판이 화면 밖으로 나갔다.** 페리가 지적해 발견했다.

사진마다 남겨야 할 높이를 CSS 변수로 따로 지정한다. 1번만 `20%`, 나머지는 `50%`.

```css
object-position: center var(--hero-focus, 50%);
```

### 최종 설정 — `260820 확정`

| 항목 | 값 | 경위 |
| --- | --- | --- |
| 넘어가는 간격 | **1.8초** | 2.5초 → 1.5초 → 1.8초 |
| 페이드 | **0.8초**, `ease-in-out` | 페리가 "급한 느낌이 있어 부드러운 움직임을 선호" |
| 노출 순서 | **1 → 4 → 2 → 3 → 5** | 파일명 순서와 다르다. 파일명은 받은 차례로 굳어 있고 순서만 목록에서 바꾼다 |

순서대로 사옥 전경 → 유압 실린더(연녹색) → 공장 내부 → 사무동 입구 → 유압 실린더(오렌지).

## 4. 사고 2건

### 캐시 — "이미지 적용이 안 되어 있어요"

배너 사진을 교체했는데 페리 화면에는 옛 사진이 그대로 보였다.
서버와 로컬의 해시를 비교하니 **동일**했다. 배포는 정상이었고 브라우저 캐시가 원인이었다.
파일 이름이 `hero-5.jpg` 그대로라 브라우저가 다시 받지 않았다.

**대응** — `build.py` 에 `asset()` 을 넣어 파일 내용 해시를 `?v=` 로 붙인다.
적용 대상은 자주 바뀌는 것들 — `style.css`, `nav.js`, `hero.js`, `gate.js`, 배너 사진 5장.

```html
<link rel="stylesheet" href="assets/css/style.css?v=1cb78a5e">
<img src="assets/img/hero-5.jpg?v=47e3ced9">
```

> 앞으로는 강제 새로고침 없이 반영된다. 다만 **이 변경이 들어간 회차 한 번만** HTML 자체가
> 캐시돼 있을 수 있어 `Cmd+Shift+R` 이 필요하다.

### 게이트 통과 직후 롤링이 멈춤

페리 제보 — "비밀번호 입력 후 진입했을 때 롤링이 멈춰 있고, 인디케이터로 수동 변경하면 작동한다."

**원인** — 검수 게이트의 "확인" 버튼이 배너 영역과 겹쳐 있다.
버튼을 눌러 게이트가 사라지는 순간 마우스 포인터가 배너 위에 얹힌 꼴이 되어 `mouseenter` 가 발생하고,
"마우스를 올리면 멈춘다" 규칙이 걸려 그대로 정지했다.
인디케이터를 누르면 `start()` 가 다시 불려 살아났던 것도 같은 이유다.

**대응** — 배너에는 누를 링크가 없어 hover 로 멈출 이유가 없으므로 그 규칙을 뺐다.
키보드 포커스로 멈추는 동작은 남기되, 포커스를 쥔 요소가 사라지는 경우까지 감안해
`focusout` 뒤 `activeElement` 를 확인하고 재개한다.

같은 조건으로 재현해 확인했다 — 게이트 통과 후 마우스를 배너 위에 둔 채 4초간 두 번 넘어갔다.
